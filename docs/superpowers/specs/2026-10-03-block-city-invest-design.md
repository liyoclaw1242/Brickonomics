# 積木城市：股票／債券／基金／ETF 互動教學 — 設計規格

- 日期：2026-10-03
- 狀態：設計已確認，待使用者審閱規格
- 專案目錄：`block-city-invest/`

## 1. 目標與受眾

- **受眾**：完全分不清股票、基金、ETF 的新手。
- **目標**：用可互動的 three.js WebGL 場景，讓使用者透過「切割」「拆開」「鑽探」親手看懂各種商品的組成、配息、費用與風險。
- **成功標準**：完成引導關卡後，使用者能回答：
  1. 股票、債券、基金、ETF 各是什麼，差在哪裡
  2. 為什麼 0050 不如想像中分散
  3. 配息為什麼不是白送的（除息），以及「配息可能來自本金」的意思
  4. 前收型與後收型基金的費用差別
  5. 同時買 QQQ 與 SPY 為什麼會重複持有 NVDA

### 納入
- 股票、公司債、國家債、基金、ETF
- 配息、除息、填息與貼息、累積型與配息型、配息來自本金（示意）

## 3. 核心比喻

### 主線：積木城市（方向 A）
- **公司**：一棟由方塊（voxel）組成的大樓。高度以**對數比例**呈現市值，並在介面上註明。
- **股票**：從大樓抽出的一顆方塊，代表所有權。
- **債券**：借錢給大樓，換到一顆「借據方塊」，固定滴出金幣（利息），不會跟著大樓長高。
  - 國家債：借給市政廳或中央銀行，鑽石材質
  - 投資等級公司債：金屬材質
  - 高收益債：有裂紋的玻璃材質
  - 可轉債：借據裡包著一顆股票色核心，條件成立時會「孵化」成股票方塊
- **基金**：怪手（經理人）主動挑選方塊，堆成小塔；會換股，要收費。
- **ETF**：照藍圖（指數）自動取方塊，壓縮成一顆彩色混合方塊，放在交易所櫃台上即時交易。
- **籃子內的方塊數量嚴格依照權重**，不失真。

### 進階：地質鑽探（方向 C，作為城市的地下室）
- 城市底下的土層就是產業分類。
- 市值型 ETF 是垂直貫穿各地層的岩芯；產業或主題型是沿某一層水平挖；高股息型是專挑會冒金幣的礦脈。
- 黃金是地底的金礦脈：不是公司，也不產生利息。

### 世界觀
- **台灣島**：2330 台積電是最高的塔；0050、安聯台灣大壩從這裡取方塊。
- **美國大陸**：NVDA、TSLA 是地標；QQQ、SPY 從這裡取方塊。
- **港口**：境外基金的怪手會跨海兩邊挑方塊。

## 4. 貫穿全程的系統

### 4.1 金幣水滴（配息）
- 來源看得見：股票是屋頂冒出股利，債券是借據滴出利息，基金和 ETF 把內部收到的金幣收集起來再發放。
- **除息守恆**：配息時方塊縮小，縮小的量等於金幣，畫面同時顯示「方塊價值 + 手上金幣 = 不變」。之後長回原狀是填息，長不回去是貼息。
- **配息來自本金**：怪手把塔上的方塊削下來熔成金幣，塔越來越矮。**只用示意基金演示**，不套在任何真實基金上；真實基金的資料面板只顯示官方揭露的配息組成數字，不另外評論。
- **累積型與配息型**：配息型的金幣掉進口袋；累積型的金幣熔掉後長成新方塊加回塔上（複利）。
- **配息頻率**：用時間軸呈現各商品實際的發放頻率。

### 4.2 費用三道門
- **入口門**：前收型基金被削掉一層方塊；股票和 ETF 只被削掉券商手續費的一小片。
- **持有中**：每個商品頭上的計費表持續把方塊磨成粉（內扣費用）。後收型多一個分銷費計費表。
- **出口門**：後收型有遞延手續費（CDSC）閘門，隨持有年數下降到零；股票和 ETF 收證交稅與手續費。
  - 這裡的證交稅是交易成本，屬於費用，不屬於「稅務」範圍。
- **持有年數拉桿**：前收型、後收型、ETF 並排，比較剩下的塔高。交叉點用實際費率計算，**不寫死結論**。

## 5. 關卡流程（混合式：引導關卡 + 沙盒）

| 關卡 | 內容 | 學習重點 |
|---|---|---|
| 序章 | 鏡頭從雲端降落，經過兩座島 | 大樓 = 公司，方塊 = 股票 |
| 1. 拿走一顆方塊 | 抽出 2330 的方塊，拉時間軸；換成 TSLA 比較波動；第一次看到股利與除息 | 股票是所有權；個股波動 |
| 2. 借錢給大樓 | 公司債與國家債的借據方塊；固定滴出利息 | 債權與股權的差別；信用品質 |
| 3. 怪手的小塔 | 四檔基金的小塔，拆開看內容；換股；前收與後收加年數拉桿；累積型與配息型；配息來自本金（示意） | 主動管理、費用、配息機制；「多重資產」內容各不相同 |
| 4. 照藍圖壓縮 | 0050、QQQ、SPY 的混合方塊；切割看權重；交易所櫃台即時價格 | 指數化、低費用、盤中交易 |
| 5. 假設情境 | 假設 2330 下跌 30%；股票、債券、ETF 受到的衝擊；QQQ、SPY、駿利平衡、安聯收益成長的重疊連線都指向 NVDA；只看配息與看總報酬的比較 | 集中度、重疊持股、總報酬 |
| 6. 鑽進地底（進階） | 產業地層、岩芯與水平挖掘、金礦脈 | ETF 的種類；黃金是另一種資產 |
| 沙盒 | 破關後解鎖；任何標的都能切割、拆開、鑽探，並開啟三道門面板 | 自由探索 |

- 所有情境都寫成「假設⋯⋯會發生什麼」，不做預測。
- 情境計算的基準：2330 下跌 30% 時，0050 約下跌 57.35% × 30% ≈ 17.2%（只計 2330 的直接影響）。

## 7. 技術架構

- **技術選型**：Vite + TypeScript + React Three Fiber + drei + zustand；資料用 zod 驗證；測試用 Vitest 與 Playwright。

```
src/
├─ data/     靜態快照 JSON 與 zod schema
├─ sim/      純 TypeScript 計算邏輯（不碰畫面）
├─ store/    zustand 全域狀態
├─ scene/    R3F 3D 元件
├─ levels/   關卡腳本（宣告式設定）
└─ ui/       2D 疊層介面與文字資源
```

### 7.1 資料模型（示意）
```ts
type Asset = {
  id: string; name: string;
  type: 'stock' | 'govBond' | 'corpBond' | 'highYieldBond' | 'convertible' | 'gold' | 'etf' | 'fund';
  region?: 'TW' | 'US' | 'GLOBAL';
  holdings?: { id: string; weight: number }[];   // 可巢狀（基金持有子基金）
  fees?: { frontLoad?: number; backLoad?: number[]; distribution?: number; expenseRatio?: number };
  distribution?: { frequency: 'monthly' | 'quarterly' | 'semiannual' | 'annual' | 'none' };
  asOf: string; source: string[]; verified: Record<string, boolean>;
};
```

### 7.2 `sim/` 模組
- `holdings`：攤平巢狀持股
- `overlap`：兩個商品之間的重疊持股
- `dividend`：除息守恆、填息與貼息、累積型的再投資
- `fees`：三道門費用、隨持有年數變化的成本曲線、前收與後收的交叉點
- `scenario`：假設情境的衝擊傳遞
- `allocate`：用最大餘數法把權重換算成方塊數量，總和必須等於上限

### 7.3 `scene/` 元件
`City`、`Building`、`StockBlock`、`BondBlock`、`EtfCube`、`FundTower`、`Excavator`、`Slicer`、`Exploder`、`CoinDrip`、`TollGates`、`Underground`

### 7.4 資料流
`data` → `sim` → `store` → `scene` / `ui`。關卡只透過 `store` 下指令，不直接操作 3D 物件。

## 8. 互動與視覺

| 動作 | 桌機 | 手機 |
|---|---|---|
| 切割 | 拖曳畫出切面，滾輪調整深度 | 單指拖曳，自動吸附到水平、垂直、斜切 |
| 拆開 | 按住空白鍵或拖動拉桿 | 雙指張開或拖動拉桿 |
| 鑽探 | 選取鑽頭後點地面 | 同桌機 |
| 檢視方塊 | 點擊 | 長按 |

- 每個手勢都有拉桿作為備案。
- 視覺：低多邊形加方塊、柔和光影；股票方塊依產業上色，借據方塊用材質表示信用品質，金幣一律金色。
- 場景固定使用白天配色；UI 疊層跟著系統切換深淺色。
- 手機直式時，資料面板改成底部抽屜。
- 只做繁體中文，文字集中在單一資源檔。

## 9. 效能

- 目標：桌機 60fps；中階手機 30fps 以上；首次載入 4 秒內。
- 一種材質一個 InstancedMesh。
- 籃子方塊數上限：桌機約 1,000 顆，手機約 300 顆。
- 依裝置效能自動降級：減少方塊、關閉陰影、降低金幣粒子數量。
- 地底章節延遲載入；打包時拆分程式碼。

## 10. 錯誤處理

- 不支援 WebGL：顯示靜態說明圖卡，內容與關卡文字一致。
- 幀率持續低於門檻：自動切換到降級模式，並告知使用者。
- 資料：在建置階段用 zod 驗證，包括權重總和接近 100%、必填欄位、日期格式；不通過就建置失敗。
- `verified: false` 的欄位在介面上顯示「待驗證」標籤。

## 11. 測試

- **`sim/` 單元測試（Vitest）**：權重攤平、重疊持股、除息守恆、累積複利、前收與後收的交叉點、情境衝擊（2330 跌 30% → 0050 約 −17.2%）、最大餘數法方塊分配。
- **資料驗證**：每份資料檔都必須通過 schema 檢查。
- **關卡流程（Playwright）**：每關都能通關，並對關鍵畫面截圖。
- **手動**：實機測試手機手勢。
